# XuegerOS 驾驶舱 · UI 设计外包 Brief

## 1. 一句话

给 DeepSeek Harness 的右侧栏做一页「小车驾驶舱」：实时相机 + YOLO 检测框 + 车体遥测 +
有界点动 + AI 接管开关，视觉必须长得像 DSH 自己的界面，而不是一个外挂控制台。

## 2. 使用场景

- 用户坐在电脑前，DSH 窗口右侧栏一直开着这页。
- 画面里能看到小车摄像头看到的东西，检测框实时跟随。
- 用户点方向键让车走一小段；或者把「允许 AI 运动」打开，让会话里的 Agent 接管。
- 网络/相机/网关随时可能掉线，界面要能一眼看出「现在能不能动、为什么不能」。

## 3. 设计范围

只设计 **DSH Web GUI 右侧停靠栏** 里的一页，尺寸约束：

- 常规宽度 360–420 px，高度随窗口。
- 支持右栏「全屏」形态：宽度约 1200–1440 px，此时布局可加宽（例如视频更大、控制区并排）。
- 窄到 300 px 仍要可用（按钮不换行、D-pad 不裁切）。

不做：独立网页、手机 App、对话区改版、设置页改版。

## 5. 状态矩阵（必须都出稿）

| 维度 | 状态 |
|---|---|
| 相机 | streaming / connecting / disconnected / 未配置 |
| 推理 | ready / starting / model_unavailable / inference_failed |
| 网关 | 离线 / 影子模式 / 物理模式 / 令牌缺失 |
| AI 授权 | 关 / 开（危险态，需要视觉强调） |
| 检测 | 空 / 1 个 / 多个 / 低置信度 |
| 运动 | 空闲 / 脉冲中 / 停车中 / 被拒绝 |
| 全局 | 加载中 / 正常 / 部分降级 / 全离线 |

错误态要区分：相机断流、网关未启动、隧道断开、越权命令。

## 6. 视觉规范（硬约束）

必须使用 DSH 主题 token，不写死颜色；下面这些是当前实现用到的：

```text
--dsw-alias-bg-layer-1 / bg-layer-2        背景
--dsw-alias-label-primary / secondary / tertiary  文字三级
--dsw-alias-border-l1 / l2                 边框
--dsw-alias-state-business-primary         正常/主操作（绿）
--dsw-alias-state-error-primary            错误/危险（红）
--dsw-alias-interactive-bg-hover           悬停底
--dsw-specific-sidebar-fill                侧栏底
--dsw-font-xs-13 / xxs-12 / mono           字体
```

- 暗色 + 亮色两套；默认暗色。
- 字号 11/12/13；正文 12，标题 13 半粗；数字用 tabular-nums。
- 圆角：卡片 10，按钮/输入 8，胶囊 999。
- 间距：4 的倍数；栏内 padding 12；卡片内 9–10；元素 gap 6–8。
- 边框 1px；不用重阴影，最多 0–1 级。
- 按钮高度 28–32；D-pad 单键 40×40，间距 6。
- 开关 34×20，圆点 14。
- YOLO 框：person 用红色 `rgba(255,92,92,.95)`，其它用绿 `rgba(78,214,166,.95)`；
  线宽 1.5；标签黑底彩字 10px。可在设计稿里给出更系统的两档语义色。
- 图标：线性 16/20/24px，1.5px 描边；方向键可用实心三角。
- 动效：150–220ms ease；遵循 `prefers-reduced-motion`。

## 7. 交互规范

- D-pad：单击 = 一次 320ms 脉冲；按住 = 每 420ms 重复脉冲；松开即停。
- 「停车」永远可点，视觉上比方向键更醒目。
- 「允许 AI 运动」开启前必须二次确认（文案已写好，可设计成 DSH 风格 Modal）。
- 网关离线时 D-pad 禁用，并在原地说明原因 + 提供「启动运动网关」。
- 所有按钮提供 hover / active / focus-visible / disabled 四态。
- 错误提示不遮挡「停车」。
- 键盘可达；开关用 `role="switch"` 语义，方向键支持长按（keydown/keyup）。

## 9. 验收标准

- 与 DSH 现有侧栏（文件树/终端）并排时，看不出是第三方页面。
- 360px 下无横向滚动、无裁切；全屏下不空旷。
- 暗/亮切换不出现对比度不足；文字对比度 ≥ 4.5:1。
- 所有状态在 Figma 里可点到；没有「设计师口头描述」的状态。
- 设计稿标注能直接映射到第 6 节的 token；出现新 token 需单独列出并说明用途。
- 不引入照片/插画/重纹理；整体是工具型界面。

## 10. 边界（不要做）

- 不要改成 Dashboard 大屏、不要加地图/雷达可视化（当前没有数据）。
- 不要用第三方 UI 组件库的默认视觉（Ant/MUI 等）。
- 不要改变功能顺序与操作语义（方向键、停车、AI 开关的位置是安全相关的）。
- 不要给「允许 AI 运动」设计成低对比、难点的开关；它必须显眼且难误触。
